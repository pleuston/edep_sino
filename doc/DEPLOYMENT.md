# EDEp Sino — Deployment

## The production image

`Dockerfile` is a two-stage build: the builder compiles both XAR packages
(`ant xar-local`, `data-pkg/ant`) and downloads the pinned library
dependencies (roaster 1.12.1, jinks-templates 1.4.1, tei-publisher-lib 6.1.0);
the runtime stage is `existdb/existdb:6.4.0` with everything placed in
`/exist/autodeploy` — numeric prefixes enforce the install order
(libraries → data package → application).

```sh
docker compose up -d        # builds on first run; app on http://localhost:8080/exist/apps/edep-sino/
```

The compose file mounts the named volume `exist-data` over `/exist/data`:
**all research data lives there** (the autodeployed packages only seed it on
the first boot of an empty volume).

Verified end to end: a cold `docker compose up` from a clean checkout passes
the complete cypress suite (134 specs).

## Operations

| Task | How |
|---|---|
| Backup | `docker compose exec edep-sino tar -C /exist -cf - data | gzip > backup.tar.gz` — or eXist's backup tools on `/db/apps/edep-sino-data` |
| Logs | `docker compose logs -f edep-sino` (the image has no shell; use `docker cp …:/exist/logs/exist.log .` for files) |
| Change admin password | first action after first boot: `http://…/exist/apps/dashboard/` → User manager |
| App upgrade | rebuild the image (`docker compose build`) and `docker compose up -d`. **Note:** with a populated `exist-data` volume the autodeploy of same-version packages is skipped; install the new XAR through the dashboard or bump the version in `expath-pkg.xml` so autodeploy picks it up. Data-package upgrades must not overwrite live data — see below. |
| Reset (destroys data) | `docker compose down -v` |

### Upgrading without losing data

The application package is stateless — reinstalling it is always safe
(ODD transforms are regenerated by its post-install). The **data package
is the seed only**: never `repo:remove` it on a live system. To migrate
vocabulary/taxonomy updates into a live database, store the changed files
into `/db/apps/edep-sino-data/data/taxonomy/` individually (`doc/DEVELOPMENT.md`
has the one-line curl) — or export the data, reset, reinstall, re-import.

## Continuous integration

`.github/workflows/build.yml` builds both XARs, validates the demo content
against EpiDoc, builds the production image, boots it and runs the full
cypress suite; XARs are attached as build artifacts.

## Remote deployment

Any Docker host works: copy the repo (or push the built image to a registry),
`docker compose up -d`, put a TLS-terminating proxy in front of port 8080
(set `proxy_set_header X-Forwarded-Host` so eXist builds correct URLs).
Choosing and provisioning the target host is deliberately out of scope here.
