# EDEp Sino — Architecture

*Living document; updated at every milestone. State: M0 (baseline after rename).*

## What this application is

A [TEI Publisher 10](https://teipublisher.com/) application, generated by [Jinks](https://github.com/eeditiones/jinks), for cataloguing and editing **Chinese inscriptions** as EpiDoc TEI. It descends from [eeditiones/edep](https://github.com/eeditiones/edep) ("Editing Tools for Digital Epigraphy"). The editor works directly on the EpiDoc XML in the browser: [Fore](https://jinntec.github.io/Fore/doc/index.html) form controls are bound to XPath locations in the TEI document; saving submits the whole document back to eXist-db.

## The two packages

| Package | eXist target | Contents |
|---|---|---|
| **edep-sino** (this repo root) | `/db/apps/edep-sino` | The application: pages, editor, API, ODDs, styling |
| **edep-sino-data** (`data-pkg/`, created in M5) | `/db/apps/edep-sino-data` | All content: inscriptions (`data/workspace`), places/people entity files, controlled vocabularies (`data/taxonomy/*.xml`), register documents, Zotero cache |

App code never stores content; `$config:data-root = /db/apps/edep-sino-data/data` (see `modules/generated-config.xql`). This separation lets the app be reinstalled/upgraded without touching research data.

## Runtime stack

```
Browser:  pb-components 3.x (web components, CDN-pinned via context.json)
          Fore (forms engine, bundled locally via ant xar-local)
          jinn-codemirror (XML/Leiden+ editing, added in M2)
eXist-db ≥ 6.2
  ├─ jinks-templates 1   (page templating: front matter + [% ... %] / [[ ... ]])
  ├─ tei-publisher-lib 6 (TEI Processing Model: ODD → XQuery transforms)
  ├─ roaster 1           (OpenAPI router: modules/lib/api.json + registers-api.json + custom-api.json)
  └─ this app + the data app
```

## Key mechanisms

- **Page rendering**: requests hit `controller.xql` → `modules/lib/api/view.xql` → jinks-templates expands the page's front matter (`extends` a layout) and `[% block %]`s. No eXist html-templating.
- **ODD pipeline**: `post-install.xql` compiles each ODD in `config.json#odds` into XQuery transform modules under `transform/` via tei-publisher-lib (`pmu:process-odd`). Rendering calls `$pm-config:web-transform`.
- **Registers**: authority data as standOff TEI docs (`pb-persons`, `pb-places`, `pb-bibl`) in the data app under `registers/`; Fore entry-forms are *data-package* templates (`registers/templates`) served by the registers API.
- **Editor (from M2/M3)**: `templates/pages/edit.html` hosts an `<fx-fore>` model bound to an EpiDoc instance; modular form sections live in `templates/parts/edit/`; EpiDoc skeleton/templates in `templates/fore/`; persistence via `/api/inscription` (POST = save), fragments as separate TEI docs linked through `TEI/@fragments` / `@corresp`.
- **Chinese layer (from M4)**: encoding decisions in `doc/sino-model.md`; era-date conversion service `modules/sino/` + `/api/sino/*`; vocabularies and nianhao table in the data package.

## Upgradability

Three independent update channels, by design:
1. **Upstream code** — `git merge upstream/edep-jinks` (see `doc/UPSTREAM.md`).
2. **Generator regeneration** — only for config-driven concerns; the manifest protects user-modified/unknown files.
3. **Library XARs** — eXist package manager updates tei-publisher-lib/roaster/jinks-templates within the semver ranges in `expath-pkg.xml`.
